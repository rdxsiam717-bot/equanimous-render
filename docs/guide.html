Setup & Guide

This site has no backend and no account of its own. It talks to GitHub's API with a Personal Access Token (PAT) that you create once and paste here. The token is stored only in this browser's local storage and is sent only to api.github.com. It is never shown in full again — only its last 4 characters.

Checking…

Step 1 — Create a token on GitHub

  1. Open github.com/settings/tokens?type=beta (fine-grained tokens) and sign in as rdxsiam717-bot.
  2. Click Generate new token. Give it a name like equanimous-voice-studio.
  3. Set Repository access to Only select repositories and choose rdxsiam717-bot/equanimous-render — nothing else.
  4. Under Repository permissions, set:
    • Contents — Read and write (upload and delete voice clones in references/)
    • Actions — Read and write (start voiceover runs, read their status, download artifacts)
    Leave everything else at No access.
  5. Set an expiry (a long one is fine, e.g. 1 year) and click Generate token. Copy the token shown — GitHub shows it only once.

If you use the wrong account (your personal GitHub account instead of rdxsiam717-bot), the token will not have access to this repo and the site will show a 404/403 error. That is the first thing to check.

Step 2 — Paste the token here

Stored in this browser's local storage under the key eq_voice_studio_pat_v1. Clearing your browser's site data removes it. To revoke it entirely, delete the token at github.com/settings/tokens.

Step 3 — Upload your voice

Go to My Voices and upload a 5–10 second recording of clear speech in a quiet room. For the best clone, read two motivational lines with the exact energy you want in the videos — warm, confident, encouraging. The file is saved in the repo as references/<name>.wav and becomes a clone you can pick every time.

A clone is a reference recording, not a trained model. Nothing about your voice is trained or stored anywhere except that file in your own repo.

Step 4 — Generate a voiceover

Go to Generate, pick a clone, choose a provider, paste the script and press Generate. The workflow runs on GitHub's free runners (public repos have no minute cap). A 60-second voiceover usually takes a few minutes, including the runner starting up. When it finishes, download the MP3 from the same page.

Providers

Chatterbox Nano — main

An open-source text-to-speech model (MIT licence) built for CPU. It clones your reference voice, so the narration sounds like you, with natural pauses and expression. It is the default for every generation.

Kokoro — fallback

An open-source text-to-speech model (Apache 2.0 licence), very fast on CPU, with a fixed set of voices. If Chatterbox fails, the workflow automatically falls back to Kokoro's male voice bm_daniel at the speed you chose. You can also force Kokoro on the Generate page.

Both licences allow commercial use, which matters because the channel is monetised. The provider actually used for each voiceover is written into the summary that comes back with the MP3.

How the site works, and what it never does

  • No backend. Every page is a static file served by GitHub Pages. All work happens in your browser and on GitHub's runners.
  • Your token goes only to api.github.com. It is never sent to any other site, never logged, and never displayed in full.
  • Your voice stays in your repo. Reference recordings live under references/ in rdxsiam717-bot/equanimous-render and nowhere else.
  • Nothing is published automatically. Generating a voiceover only creates an MP3. Uploading or scheduling a video is a separate, deliberate step in the n8n pipeline.

Troubleshooting

  • “Resource not found” (404) when loading voices or dispatching: the token is from the wrong GitHub account, the repo is not selected in the token's repository access, or the chatterbox-voiceover.yml workflow has not been pushed to the repo yet.
  • “Bad credentials” (401): the token was typed wrong, expired, or revoked. Create a new one and paste it again.
  • “Forbidden” (403): the token is missing the Contents or Actions permission. Edit the token on GitHub (or create a new one) with both set to Read and write.
  • The run stays queued for a long time: GitHub's free runners are usually fast, but queues happen at busy times. Open the run on GitHub to watch it directly.
  • The MP3 download button does not appear: the artifact zip could not be unpacked in the browser (the JSZip CDN may be blocked). Use the “Download artifact zip” button instead — it contains the same MP3.
